# Category II–IV theologian candidates

This is a review registry, not an addition to the verified production catalogue. The 858 source records are retained verbatim in `source.json` and represented once in `authors.json` (II: 242, III: 406, IV: 210). Source SHA-256 is recorded in the generated JSON. Names, eras, traditions, and categories are unverified candidate labels; the categories are organizational groupings, not endorsements. This registry makes no claim that works or texts are available.

Regenerate with `python3 build_candidates.py`. This writes only `authors.json`; it never edits `../catalogue.json`. The page at `index.html` supports accent-insensitive search, filters, and pagination. Normalized names are used only to report possible collisions; no records are merged.

Before production import, reviewers must record sourced verification for identity, lifespan, theological attribution, and at least one relevant theological work composed by 1900. Each evidence item needs an authority URI or identifier, reviewer, short claim, and valid ISO `reviewedAt` date. Identity evidence needs a stable `personIdentity` identifier. Lifespan evidence must contain integer `birthEarliest`, `birthLatest`, `deathEarliest`, `deathLatest`, and an `uncertainty` note. Attribution evidence must identify `attributedAuthorIdentity` and match the verified person identity. Pre-1901 work evidence must contain `workTitle`, matching `attributedAuthorIdentity`, and a `compositionDateUpperBound` no later than 1900. Rights are reviewed separately. Any proposed edition entered under `proposedEditions` and marked `ingested` must have `rightsVerified: true`, a licence, and a source URL. The `--eligible` check lists only records meeting this evidence-completeness gate; it does not itself import them or establish that the claims are historically true. The current list has zero records passing the gate.

Run validation tests with `python3 -m unittest discover -s tests -v` from this directory.
